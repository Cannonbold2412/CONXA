# Product

## Register

brand

## Platform

web

## Users

Two co-equal primary audiences arrive on this marketing surface: SaaS company builders (product/eng leads deciding whether to ship AI-native capability to their customers without building it themselves) and enterprise ops buyers (ops/finance/support leaders with repetitive internal software work they currently pay humans to do). Both land here mid-evaluation, comparing Conxa against RPA, native API integrations, or sending a raw AI agent at their live UI, and both need to leave believing this is the reliable option before they'll book a conversation.

## Product Purpose

Conxa records a human performing a software workflow once, in the Build Studio, and compiles that recording into a self-healing skill an AI agent can execute reliably forever after — without the target application exposing an API or the vendor building an integration. This page exists to get a qualified SaaS or enterprise evaluator to believe that claim enough to book a demo.

## Positioning

Conxa makes any existing web application directly, reliably operable by AI agents — no API, no code changes to the target application, and no agent re-discovering the interface from scratch on every run.

## Conversion & proof

Primary CTA: book a demo / talk to sales — the product's core trust claims (self-healing recovery, local execution, enterprise safety) need a conversation before a self-serve signup would convert.
Secondary CTA: read the docs — a fallback for technical evaluators who want to go deeper before talking to anyone.
The line a visitor should remember after 10 seconds: Conxa makes any existing web app directly, reliably operable by AI agents.
Belief ladder:
1. My product's (or my team's internal) workflows aren't reliably operable by AI agents today.
2. The alternatives all break or don't scale — RPA encodes brittle selectors, native API integrations are expensive and slow to build, and sending a live agent at the UI burns tokens and fails inconsistently.
3. Conxa solves this without me writing code — record once, compile once, run forever.
4. Execution stays local on the customer's machine; the cloud only coordinates. Safe for an enterprise security review.
5. This is worth a fifteen-minute conversation to see it work on my own product.
Proof on hand: none yet. Page should lead with product credibility — how the recording/compile/execute architecture works, not logos or testimonials — until real proof exists.

## Brand Personality

Technical and credible first: the page should read like infrastructure a senior engineer would trust, not a hype deck. That credibility carries genuine category-defining confidence — Conxa is naming and claiming a new layer (agent-operable software), so the tone can be bold about that claim without leaning on gradients or superlatives to sell it. Underneath both, an enterprise-safe calm: nothing about the page should feel risky, unproven, or move-fast-and-break-things. Precision and restraint are what make the boldness credible, not louder claims.

## Anti-references

Do not look like the generic AI/SaaS template: no gradient-clip text, no cream/sand near-white body background, no tiny uppercase tracked eyebrows above every section, no identical icon-heading-text feature card grids. Do not look like legacy RPA/enterprise software either: no dense sales-brochure layouts, no cluttered feature-matrix tables, no stock-photo "enterprise team in a meeting" imagery. References for the right register: Vercel, Linear, and Anthropic's own site — dark, technical, restrained color use, sharp typography, product substance over illustration.

## Design Principles

- Credibility over hype: every claim about self-healing recovery, local execution, or reliability should be shown (architecture, mechanism, specificity) rather than asserted with adjectives.
- One category claim, said once, clearly: the page has a single strategic claim — agent-operable software without API work — and every section should reinforce it, not introduce competing claims.
- Calm confidence, not urgency: no countdown timers, no manufactured scarcity, no exclamation-point energy. The enterprise-safe read comes from restraint.
- Technical audience, technical proof: prefer showing the actual pipeline (record → compile → skill → execute) over marketing abstractions like "AI-powered" or "next-gen."
- Two audiences, one page, no false split: SaaS builders and enterprise ops buyers share the same core belief ladder: don't fork the page into two visibly separate pitches.

## Accessibility & Inclusion

WCAG 2.1 AA baseline. `prefers-reduced-motion` must be respected throughout (index.css already does this for scroll behavior — extend the same care to any new hero/3d/motion work introduced on this page).
