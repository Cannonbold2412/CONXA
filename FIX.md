## Planned: the compiler will ask a few quick questions instead of silently guessing — 2026-09-13
When a recording is turned into an automation, the system quietly guesses things only the person who recorded it really knows — like whether a typed name should be the same every time, or whether an uploaded file should change on each run. A wrong guess about a file upload is especially bad: the file sits on the recorder's computer, so the automation breaks for every customer. The plan is for the review screen to show a handful of simple multiple-choice questions, only when the system is genuinely unsure, and never stop the build to wait for answers. No code changed yet; it is now written down as priority work.

## The reviewer's screen now offers to fix a common recording mistake with one click — 2026-09-13
Automations that download one specific file and upload it somewhere else are extremely common in back-office work, but recording one only ever captures a single example file — the finished automation could only ever handle that one file, not "however many files the customer names." Now, when someone reviews a freshly recorded automation, the screen automatically notices this exact pattern and offers a button: "generalize this to any number of files?" One click rewrites it to ask the customer which files they want, every time it runs. Nothing is guessed by AI here — the system only offers this when it can see, from the recording itself, that the file's name shows up plainly in a web address, so there's no risk of it getting confused. The suggestion never applies itself; a person always has to click Accept, and clicking "no thanks" means it won't ask again for that same automation.

## Fixed a "download from GitHub, upload to Drive" automation that only worked for one specific file — 2026-09-13
An automation recorded once against a single named file (an example ".gitignore" template) could only ever download and upload that exact file, no others — like a copy machine that only photocopies one particular page no matter what you feed it. It now asks which file or files to grab (one, a few, or many, separated by commas), downloads each one in turn, and uploads all of them to Drive together, keeping every file's own name and content intact. Fixing this also uncovered two smaller bugs in how the system decides what questions to ask a user: it was sometimes accidentally turning an already-automatic value (like "whatever file was just downloaded") into a question the user had to answer by hand, and it could ask about a loop's own internal counter as if it were a real setting. Both are fixed, which makes every "repeat this for a list of things" automation more reliable, not just this one.

## Fixed the "generalize to a loop" button producing a loop that downloaded nothing — 2026-09-13
After the previous fix shipped, the reviewer tried it for real: re-recorded the download-and-upload automation, clicked the new "generalize this" button, and ran it — it opened the file's page and did nothing else, over and over, uploading no files at all. The cause was a cleanup step in the recording process that quietly removes clicks it thinks had no effect, using "did the page visibly change?" as its test. A click that starts a file download never visibly changes the page — that's normal, not a sign it's useless — but the cleanup step couldn't tell the difference, so it had deleted the exact click that starts the download. The same blind spot had already deleted a different click (the one that opens the upload picker) in the very first version of this automation, so this wasn't a fluke — it was a rule that would keep breaking things. That rule is now taught to recognize "this click's job is to start a download or open a file picker" and leave those alone. A second, smaller leftover was also cleaned up: a hardcoded click on the one example filename that used to sit outside the new loop, doing nothing useful once the loop visits each file by name directly — the "generalize" button now removes that stray click too, keeping a full record of what it removed in case anyone wants it back.

## Fixed the "generalize to a loop" button not appearing at all for some filenames — 2026-09-13
Right after the previous fix, the reviewer tested again with a different example file — one whose name has a "+" in it — and this time the "generalize this" button didn't show up at all, no error, nothing. The cause: web addresses can't contain certain characters directly, so a browser writes them in a scrambled, encoded form behind the scenes (a "+" becomes "%2B") — like a street address getting typed into a form that only accepts phone-book codes. The system was comparing the plain filename against that scrambled address and never finding a match, so it assumed the pattern it looks for wasn't there. It now un-scrambles the address before comparing, so it correctly recognizes the file no matter what characters are in its name — spaces, symbols, or anything else a browser would encode.

## An automation that downloads files can no longer say "done" while quietly downloading nothing — 2026-09-13
After the last fix, the reviewer tried the whole automation again with real filenames — and it ran without any error message, but nothing actually downloaded. The step responsible for noticing "a file just finished downloading" was designed to simply wait quietly and move on if no download ever showed up, with no complaint at all — like a delivery person who shrugs and drives off if nobody answers the door, instead of leaving a note. That meant an automation could report success while secretly skipping some, or even all, of the files it was supposed to grab. That step now speaks up immediately if a download doesn't happen, stopping the automation right there and saying exactly which file went missing, instead of pressing on silently. A related gap was closed at the same time: if an automation is told to keep going even when one item fails, it now clearly reports how many items it had to skip, instead of only recording that privately for internal diagnostics.
