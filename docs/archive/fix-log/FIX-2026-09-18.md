# Fix Log — 2026-09-18

## Found why the software never updated itself on customers' computers, and simplified the release process to match — 2026-09-18
We dug into a report that the automatic software updater wasn't downloading new versions, on any computer, ever. It turned out the update-publishing step had a missing setting, so every release quietly failed to announce itself to customers' installs — like a delivery service that never got told the warehouse address, so it just never left the truck, without ever raising an alarm. We also found the "practice run before the real release" step it depended on pointed at a test server that had been retired weeks earlier, making that safety step impossible to use even once the missing setting is filled in. Releases now go straight out once that one setting is filled in, instead of through a two-step process that no longer has a first step to go through. The remaining action needed — filling in the correct web address and access key for releases — has been added to the project's task list for a person to complete, since it involves a private password we don't handle automatically.

## Fixed a "repeat for every file" automation that only worked for the very first file, and made a file-upload step fail clearly instead of confusingly — 2026-09-18
The one-click "turn this into a loop that handles any number of files" feature had a hidden catch: it correctly taught the automation to visit each file's own page, but it forgot to also update a second, less obvious instruction some recordings carry — one that tells a step "act only on the row containing this exact file." That second instruction was left pointing at the very first file's name forever, so only the first file in the loop ever worked correctly; every file after that quietly failed. It's now updated together with the rest, so every file in the loop is handled correctly, not just the first. Two smaller issues found alongside it were fixed too: a newly-added question the automation asks the customer (which files to grab) is now checked for mistakes before being saved, and a note this feature leaves behind for reviewers ("this old click was removed because the new loop replaces it") now survives being recompiled instead of quietly disappearing.
Separately, fixed two smaller issues in the same family as yesterday's "why did this fail" assistant fix. First: if someone edits a workflow (adds or removes a step) after a test run failed, the assistant could end up pointing at the wrong step entirely instead of noticing the workflow had changed underneath it — it now double-checks itself and says "I can't be sure which step this was" instead of confidently guessing wrong. Second: a step that uploads "whatever files were just downloaded" used to fail with a confusing technical error when nothing had actually downloaded yet — it now says plainly that the expected download never showed up, the same clear message a similar, already-working case already gives.

## The "why did this fail?" assistant in Human Edit was blaming the wrong thing when it couldn't see what actually happened — 2026-09-18
A tester ran a workflow, it failed at a real step, and then asked the built-in AI assistant why. The assistant answered confidently — but wrongly — pointing at an unrelated step further down the workflow, because the one piece of evidence that would have told it the truth (a screenshot and error log from the failed run) hadn't been recorded for that test yet. Instead of noticing "I have nothing to look at here" and saying so, it guessed, using an old note as raw material to talk itself into a story. The assistant now always checks the workflow's own saved failure message first — the same message a person can already see on screen — and if it truly has no evidence to inspect, it says that plainly instead of inventing a cause. Separately, we found and closed off the reason the richer evidence had gone missing in the first place: a broken piece of text (an accidental copy-paste of a filename alongside the actual verification code) had been silently blocking that evidence-recording feature from ever reaching this tester's version of the app. That kind of mistake now gets caught and blocked immediately, loudly, instead of quietly breaking things nobody notices until much later.
