# Fix Log — 2026-07-20

## Installing a company's skill package no longer force-closes your Claude Code terminal session — 2026-07-20

The installer used to shut down the Claude Desktop app before adding the new skills, so it could
update its settings file safely. But it was too aggressive: on Windows it shut down anything named
"claude.exe", which is also the name Claude Code (the coding assistant terminal tool) uses. So
running the installer while working in Claude Code would silently kill that session too, like
turning off the whole building's power to reset one light switch. Now the installer checks where
the program is actually installed from and only closes the real Claude Desktop app, leaving Claude
Code sessions untouched.

## Wrote the plan for making our installer work with every AI assistant, not just Claude — 2026-07-20

Right now a customer can only install a Conxa skill pack if they use Claude. Everyone on Cursor, VS Code, Windsurf and a dozen others is simply unreachable, no matter how good the pack is. We studied an open-source tool that plugs itself into 43 different assistants automatically and wrote up how to do the same here: a simple list of supported assistants that anyone can add a line to, plus a safer way of editing the customer's settings file so we never damage it. We also found a real bug along the way — uninstalling a test build leaves a dead entry behind that makes the assistant show a permanently broken connection. Nothing in the product changed yet; this is the plan and the bug report, not the work.
