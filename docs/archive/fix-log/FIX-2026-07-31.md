# Fix Log — 2026-07-31

## Fixed the "reinstall needed" test error for real this time — 2026-07-31

Yesterday's fix for the workflow-test shortcut error only made it wait a little longer and complain more clearly when it still failed — it didn't stop the failure from happening. Digging deeper found the actual cause: after a test finishes, Build Studio was switching off the test engine by force, like yanking a plug out of the wall instead of asking it to shut down properly. That meant the little helper browser it had opened never got a chance to close cleanly, and it could keep a lock on the very folder Build Studio needed to update seconds later, causing the "reinstall needed" error on the next test. Build Studio now asks the test engine to shut itself down properly first and gives it a few seconds to do so — which lets it close its browser cleanly — and only force-stops it if it doesn't respond in time. The longer wait-and-retry from yesterday stays in place as a backup for the rare cases something else is still in the way.

## Explained in the product document why customer updates reach people quickly — 2026-07-31

The program customers install is really two pieces stacked together: a big, rarely-changing base that carries the browser engine, and a small piece on top holding the logic that actually runs workflows and repairs them when a page changes. The product document described it as one lump, which hid the commercial point: because the top piece is tiny, an improvement to how workflows recover from broken pages reaches every customer as a very small download within a release, instead of a large reinstall that customers would have to agree to — and customers who have to agree usually don't. That's now written down, along with the two protections that stop fast updates from causing harm: the base refuses to run a newer top piece it's too old to support, and a failed update automatically goes back to the previous working version.

## Updated the product definition document to match what Conxa actually does today — 2026-07-31

The main product document hadn't been touched in almost a month, and it had drifted from reality in ways that would mislead anyone reading it to understand the business. It said Conxa only works with Claude Desktop — in fact the software now installs itself into more than twenty different AI assistants, including the popular coding tools, which is a much bigger market than the document described. It also had no pricing or business model section at all, even though four paid plans with real limits are live in the product. Both are now written up, along with a plain statement of which computers we support (Windows today; Mac builds exist but aren't ready for customers, so we say so rather than implying otherwise) and a section on the audit trail and access controls enterprise buyers ask for. We also removed three statements that were simply wrong: the recovery system was described as having five stages when it has four, the installer was said to hook into one assistant when it hooks into all of them, and the document claimed an assistant could check a running job's progress through a feature that doesn't exist.

## Redesigned the Input Variables screen and added an "Optional" setting — 2026-07-31

The screen where you turn a recorded value (like an email address) into a reusable variable had two problems. First, it had two different buttons that both looked like the main action — one added a blank row, the other actually saved your changes — so it wasn't clear which one to press. Second, the "replace with" box in its find-and-replace tool only accepted a short variable name, but nothing on screen said so, so typing an ordinary sentence there produced a confusing "Invalid id" error. We rebuilt the screen: variables now list as a compact table instead of a big form for each one, the confusing button was removed in favor of a single "New variable" strip, and the input that expects a variable name now visually wears the `{{ }}` braces so it's obvious what belongs there. We also fixed the "Save variables" button sometimes scrolling out of view when a workflow had many variables — it now always stays visible at the bottom, and clicking it now closes the screen too, instead of leaving it sitting open after saving. Separately, every declared variable used to be treated as required, with no way to say "this one's optional." There's now an Optional checkbox for each variable, and the AI running the workflow will no longer insist on a value for one you've marked optional.

## Made a test-engine update failure fail loudly instead of quietly breaking the next test — 2026-07-31

When Build Studio updates the local test engine it uses to run workflow tests, it swaps in the new version and then updates a shortcut that points at "whichever version is current." On Windows, that shortcut swap could occasionally fail silently right after a previous test finished, if the old files were still momentarily locked — like trying to replace a nameplate on a door seconds after someone walked out of the room. Nobody saw an error at the time; instead, the *next* workflow test would fail with a confusing "reinstall needed" message even though everything had actually downloaded correctly. The swap now retries briefly to ride out that split-second lock, and if it still can't update the shortcut, it now says so immediately and clearly instead of pretending the update succeeded and leaving the next test to fail mysteriously.

## Sped up the "Apply" button in Human Edit's re-targeting tool — 2026-07-31

When someone re-targets a step by drawing a new box around an element, the tool needs to work out two things: which button/field it is (so it can click it later) and what it looks like to a human (so it can still find it if the page changes and the exact click breaks). Both of those used to be figured out at different moments — the first right after you draw the box, the second only when you hit the final "Apply" button — so Apply could sit and think for a few seconds every time the box had moved. Now both are worked out together, right after you draw the box, so by the time you click Apply everything is already known and it applies instantly. Nothing changes if you're only touching the checks below without moving the box — that was already instant and still is.

## Fixed installed customer apps being unable to download their skills or check for updates — 2026-07-31

Every customer who installed one of our packaged apps was hitting a wall right after install: the app could never fetch its actual workflow files or check for a newer version, so its skills folder stayed empty no matter how long you waited. The cause was a security check on our servers that requires a proper login for almost everything — but a few specific requests are supposed to be let through without one, because a freshly installed app has no login yet, only a private access code baked in at build time. The list of "let these through" addresses on our server hadn't been updated to match where those requests actually go, so they were being turned away before our own code even got a chance to check the access code. The addresses have now been corrected, so a fresh install can pull down its skills and check for updates as intended.
