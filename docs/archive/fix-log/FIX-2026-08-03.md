# Fix Log — 2026-08-03

## App updates now reach customers on their very next launch, not the one after — 2026-08-03
When we pushed a code update to the program that runs skills on a customer's computer, it used to take two openings of Claude Desktop to actually show up — and if someone reopened Claude within an hour of the last check, the update check was skipped entirely and could be missed for a long time. The delay happened because the program only swapped in the new code after it had already started running with the old code loaded in memory, like trying to hand someone a new script after the play has already begun. Now the check and swap happen right at startup, before anything else loads, so a pushed update is live the very next time a customer opens Claude Desktop — matching how skill updates already worked. We also removed the hour-long waiting window on the update check, and added a safety check so a customer's older program doesn't try to load code that requires a newer version, so it degrades to what's already installed instead of failing over and over.
